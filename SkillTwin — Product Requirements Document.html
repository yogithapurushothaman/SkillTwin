SkillTwin — Product Requirements Document

Version: 1.0 (Hackathon MVP) · Date: 29 Sep 2026 · Status: Draft

1. Overview

Product: SkillTwin — an evidence-based skill intelligence and placement platform connecting students, academicians, industries and institutions.

One-liner: Turn a static resume into a living, evidence-backed skill profile (the SkillTwin) that shows what students claim, what they can demonstrate, what industry needs, and what to improve.

Core loop: Claim → Verify → Map → Gap → Improve → Re-verify → Match

2. Problem Statement

  • Resume skills are unverified; companies filter by keywords and eligibility.
  • Tests, technical interviews and HR rounds are disconnected from each other and from the student's profile.
  • Students get selected or rejected without learning why.
  • Colleges see placement outcomes but not the skill gaps behind them.
  • Industry needs change faster than curricula.
  • Internships and projects are not converted into structured skill evidence.

3. Goals and Non-Goals

Goals

  1. Build a verified, evolving Skill DNA per student from multiple evidence sources.
  2. Let industry define measurable role blueprints and match against verified skills.
  3. Surface transparent, explainable skill gaps at student and batch level.
  4. Support an improvement loop (train → reassess → updated score and match).
  5. Keep all critical scoring deterministic and reproducible.

Non-Goals (MVP)

Video conferencing, facial/emotion/biometric analysis, blockchain certificates, mobile app, real company integrations, complex recommendation algorithms, large question banks, real-time messaging, microservices/Kubernetes, advanced auth, multiple AI providers, automated hiring decisions.

4. Users and Personas

Persona Needs Key outcomes
Student Know true skill level, get actionable gaps, build evidence Higher placement readiness over time
Academician See batch-level gaps, plan interventions, track improvement Targeted training, measurable impact
Industry user Define role requirements, discover candidates by verified evidence Better shortlists, less keyword dependence
Institution admin Monitor department/batch readiness and trends Academia–industry feedback loop

5. Key Concepts

  • SkillTwin: the continuously updated profile combining claims, demonstrated evidence, industry requirements and improvement needs.
  • Skill DNA: visual per-skill scores (technical, problem solving, soft skills), each with linked evidence.
  • Verification status: 🟢 Verified · 🟡 Self-declared · 🔴 Skill gap.
  • Industry Skill Blueprint: required proficiency score per skill for a role.
  • Skill Gap Engine: rule-based comparison of verified Skill DNA vs. blueprint.
  • Placement Readiness: weighted overall score across evidence stages.

7. Controlled AI Requirements

AI is used for: resume parsing, skill normalization, assistance evaluating free-text interview answers against fixed rubrics.

AI is not used for: final placement decisions, candidate ranking logic, personality diagnosis, predicting job outcomes, inventing skills, inventing company requirements, judging intelligence, opaque decisions.

ID Requirement
AI-1 All AI outputs must be structured JSON validated against a schema before use
AI-2 Skills must map to the predefined dictionary; unknown skills are rejected
AI-3 Rubric criteria, weights and score bounds are defined by the system, not the model
AI-4 Final scores, match scores and readiness are computed by deterministic code
AI-5 If AI fails or returns invalid output, fall back to manual entry / keyword matching
AI-6 Store AI-assisted scores with a flag so they are distinguishable in evidence

8. Scoring Logic (MVP defaults)

  • Verified skill score: weighted combination of available evidence (assessment, interview, project/internship). If no assessment exists, status stays self-declared and claimed level maps to a provisional score that is visibly marked unverified.
  • Role match score: sum over blueprint skills of min(student_score / required_score, 1) × skill_weight, divided by total weight (equal weights by default).
  • Readiness bands: ≥75 Industry Ready · 50–74 Needs Development · <50 Critical Gaps (configurable).
  • All formulas and thresholds live in one config module and are displayed in the UI where relevant.

9. Primary User Journey (Demo Flow)

  1. Student uploads resume → skills extracted → Skill DNA (self-declared).
  2. Industry role selected (Software Developer Intern) → blueprint shown.
  3. Gap Engine compares student vs. blueprint → critical gaps identified.
  4. Student takes gap-prioritized online test → technical interview → HR/soft-skill assessment.
  5. Skill DNA updates to verified; placement readiness computed.
  6. Institution dashboard shows batch skill gaps.
  7. Industry dashboard shows matched candidates with evidence.
  8. Reassessment shows improvement (skill history chart).

10. Data Model

Core tables: users, students, skills (id, name, category), student_skills (student_id, skill_id, score, verification_status), skill_evidence (student_id, skill_id, source, score, ai_assisted, timestamp), industry_roles, role_skills (role_id, skill_id, required_score), assessments, questions (skill, topic, difficulty, marks), assessment_results, interviews (student_id, type, rubric scores, result), internships, skill_history (student_id, skill_id, old_score, new_score, date).

11. Technical Architecture

  • Frontend: Next.js, TypeScript, Tailwind CSS, Recharts.
  • Backend: Python, FastAPI, modular services: Resume, Skill Engine, Assessment, Interview, Matching, Placement.
  • Database: PostgreSQL (SQLite for prototype).
  • AI layer: single LLM provider called only from the backend; JSON-schema validated.
  • Resume processing: PyMuPDF / pdfplumber for text extraction.
  • Interface: REST + JSON.

12. Non-Functional Requirements

Area Requirement
Explainability Every score and match shows its inputs and formula
Reproducibility Same inputs always yield the same scores (excluding raw AI rubric inputs, which are stored)
Performance Dashboards load in <3s on demo data; resume extraction <15s
Privacy Students' data visible to industry only for roles/opportunities they participate in; role-based access control
Reliability Graceful fallback when AI is unavailable
Usability Clear, chart-driven dashboards; responsive desktop web

13. Success Metrics

Hackathon: end-to-end journey runs live without failure; visible skill improvement (e.g., DSA 42% → 68%); judges can see evidence behind every score.

Product (post-MVP):

  • % of self-declared skills converted to verified
  • Average skill-score improvement after reassessment
  • Reduction in batch-level critical gap share after interventions
  • Recruiter shortlist time and precision
  • Students completing full assessment pipeline

14. MVP Scope and Milestones

Must demo (P0): registration, resume extraction, skill dictionary normalization, Skill DNA, one role blueprint, Gap Engine, online test, technical interview, HR/soft-skill assessment, placement readiness, skill history, institution dashboard, industry candidate view. Use seeded data for ~20–30 sample students to make batch analytics meaningful.

Suggested build order:

  1. Data model, skill dictionary, seed data
  2. Skill Engine + Gap Engine (deterministic core)
  3. Resume upload/extraction
  4. Assessment + interview engines
  5. Student dashboard (Skill DNA, readiness)
  6. Institution and industry dashboards
  7. Reassessment/history chart and demo polish

15. Risks and Mitigations

Risk Mitigation
LLM extraction errors Dictionary-constrained mapping, schema validation, student review step
Free-text scoring inconsistency Fixed rubric, bounded scores, AI flag, manual override
Small question bank limits credibility Focus on 4–5 skills with quality metadata; state scalability plan
Time constraints Strict P0 scope; seed data; avoid non-goals
Bias/fairness concerns in matching Rule-based scoring, no personality inference, visible evidence
Score gaming (retakes) Randomized question selection, attempt history, cooldown (P1)

16. Open Questions

  1. Exact weighting between evidence sources when they conflict?
  2. Should industries see students by default or only those who opt in?
  3. How are mentor verifications authenticated for internships?
  4. Who owns and reviews the question bank and skill dictionary long term?
  5. Should thresholds differ by role or department?

17. Future Roadmap

Larger adaptive question banks, company/LMS integrations, mentor verification workflow, curriculum-mapping recommendations, training-effectiveness analytics, mobile app, stronger authentication and audit trails.
